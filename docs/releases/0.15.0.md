## Changes

- On application opening, an absent `config.json` now seeds an editable kit:
  common OMXTerm defaults, one snippet with `execute: false`, and a user-owned
  copy of the default palette at `themes/omtheme.json`. The configuration selects
  that theme. Any existing configuration entry skips the entire kit, including
  invalid files and dangling symlinks. Existing sibling files are never replaced.
  Reload does not create files, and creation failures do not block the terminal.
- Successive Space presses no longer depend on native `beforeinput` events that
  can stop arriving. The correction preserves composition, native Option input,
  focus, modifiers and negotiated keyboard reporting without duplicate delivery.
- Platform quick starts and the optional OMXTerm Studio editing workflow are
  documented.

No configuration schema migration is required. The intentional filesystem
contract change applies when configuration is absent at startup, not when the
package is copied or installed. A generated theme is user-owned and does not
track future bundled palette changes. No theme picker or automatic reload is
introduced.

and Windows ARM64 (8). All used temporary directories and left existing user
configuration untouched. The Windows probe did not attempt the Unix symlink
scenario. These probes are not GUI or installer evidence.

## Remaining risks and limitations

- Native VM automation does not qualify every physical GPU, desktop environment
  or native input-event source. The missing native Space event's originating
  cause remains unisolated; the correction removes its delivery dependency.
- Graphical first-opening appearance, Gatekeeper/SmartScreen presentation and
  behavior beyond automated seams remain **UNVERIFIED**. Manual testing is
  optional, not a release gate.
- macOS artifacts are ad-hoc sealed, without an Apple Developer ID signature or
  notarization. Privacy permission retention across updates is not guaranteed.
- Linux requires X11/XWayland and uses the fixed Linux-only `--no-sandbox`
  policy (ADR 0024). When kernel-FUSE mounting is unavailable,
  `--appimage-extract-and-run` is the supported fallback, not a sandbox repair.
- The Windows installer and Linux AppImage are unsigned. No package has a
  verified publisher identity or an independent security-audit guarantee.
